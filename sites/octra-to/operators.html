YOUR NODE / YOUR CHOICE

Start as a node.
Opt into exit later.

Choose a Linux VPS with a public IPv4 address, persistent SSD storage and enough CPU, memory and bandwidth for an authenticated full history. A home server with a reliable public route can also work. Dedicated resources are the safer starting point for an always-on validator. Size from a real snapshot and sustained sync measurements; we have not published a validated minimum VPS size.

01 / CHOOSE A HOST

Cloud VPS

DigitalOcean Droplets or Hetzner Cloud offer public IPs, persistent storage and firewall controls. Start with an observer, monitor resource use, then resize before seeking validator duty.

02 / SYNC OCTRA

Rust node

Build the pinned repository, generate a unique node identity, bootstrap from an independently trusted devnet config, then run octra-node as a supervised service. Keep RPC private.

03 / ADD SERVICE

Mesh first

Configure the embedded mesh and HTTPS control endpoint. Give users daemon-minted, single-use enrollment keys. A personal network does not require a paid exit or operator bond.

OBSERVE BEFORE VOTING

Bring up a verified devnet observer.

cargo build --locked --release -p octra-node
target/release/octra-node init-identity --key /private/node.key
target/release/octra-node bootstrap --config bootstrap.json --directory /private/octra-state
target/release/octra-node run-network --config network.json

The bootstrap and network files must pin the real chain origin, validator and exporter trust, config hash and checkpoint floor. Never use a config downloaded from the same untrusted snapshot as its own authority. Start with "voting": false; confirm canonical head/root, peers and restart recovery before changing role.

EXPLICIT EXIT OPT-IN

Sell traffic only when ready.

To carry other people’s Internet traffic, add canonical payments, mesh.stock_exit, a fixed stock_portal and optional paid Circle gateway to your node config. Publish a tariff in your own Circle, bond your operator wallet, expose trusted HTTPS control, configure DNS, TLS, NAT and the advertised exit, then test a finite paid purchase end to end. Without that configuration, node sync and mesh membership do not advertise a paid exit. Other nodes can join your mesh, but routing through a second operator requires a separate accepted plan for that hop.

VALIDATOR PATH

Earn chain duty separately.

Validator enrollment, stake and active membership are chain decisions. Turning on "voting": true is not enough. Verify the current devnet validator requirements and your bonded identity before enabling duty; keep the operator key and node state durable. We intend to require paid VPN operators to be Octra validators in a future protocol version. The current payment Circle does not enforce that rule.

Full configuration and recovery instructions: github.com/androolloyd/octravpn/blob/main/docs/rust-node/devnet.md and github.com/androolloyd/octravpn/blob/main/docs/architecture/stock-paid-exit.md.

OPERATOR TO OPERATOR

Build a route across
open channels.

Each operator can choose its peers, publish a signed endpoint and tariff, and accept a separate prepaid channel for the next hop. A channel balance is spendable capacity, not permission to forward. Every hop must have a confirmed finite byte purchase before carrying traffic.

YOU→ENTRY→EXIT→DESTINATION

Choose the entry you trust; it carries encrypted traffic to the next operator rather than connecting you directly to an unknown destination. The final exit still sees the destination. Today the native Linux client can run an explicitly accepted two- or three-operator route with one durable plan per hop.

The next release goal is to compare healthy exits by measured path latency and price, then propose the closest viable route for your approval. Shielded per-hop payments are required before we can call that operator network private: the current devnet Circle publicly exposes payer and operator relationships. Automatic discovery, private settlement and stock Tailscale mesh-to-mesh routing are not live.

Current manual route format: github.com/androolloyd/octravpn/blob/main/docs/architecture/nested-paid-exits.md.

01 / THE FRONT DOOR

Help people in.

Publish a small, exact allowlist of public Circle assets for instructions and offer discovery. The registration-only route cannot carry arbitrary Circle or Internet traffic.

02 / THE PAID ROUTE

Sell finite bytes.

Post a public tariff with explicit traffic classes. A user accepts a plan and signs a purchase. The node waits for canonical confirmation before it forwards those bytes.

03 / THE SETTLEMENT

Keep what you earn.

OCT moves between payer and operator. Available channel value can include earned OCT, so an exit operator can fund its own usage without first moving earnings out.

THE RULES ARE VISIBLE

Price freely.
Change carefully.

The current devnet payment Circle delays a new rate for 24 hours, giving payers time to leave. A payer can withdraw available channel OCT immediately; settled purchases stay final. An operator’s stake has a seven-day unstake period. Service still depends on a reachable control plane, canonical state and working routes.
